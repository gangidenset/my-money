# my-money

「自分の収入なら、どこまでお金を使っていいのか分かる」スマートフォン向け家計アプリ。

## 起動

```bash
npm start
```

http://localhost:8080 を開く。ビルド不要（HTML / CSS / JavaScript の ES Modules）。

## テスト

```bash
npm run test:all
```

`npm run lint`（読み込み忘れの検出）・`npm test`（計算・オフライン）・`npm run test:e2e`（画面操作。Windows では Edge を使用）を順に実行する。GitHub では、すべて通ったときだけ公開される。

各画面のボタン操作は、画面ごとのファイルの `○○Actions`（data-action 名 → 処理）にまとめている。
依存の向きは core ← ui ← views ← app の一方向のみ。

UI → dataService → storage の順にだけ依存する。データは端末内にのみ保存し、外部送信はしない。

## 保存データの版管理

- 保存データには形式の版（`schemaVersion`）を記録する。形式を変えるときは `dataService.js` の `SCHEMA_VERSION` を上げ、`MIGRATIONS` に「その版への変換」を追加する
- 起動時に古い版のデータを1版ずつ変換する。変換前のデータは端末内の `preMigrationBackup` に残る
- 新しい版のアプリで保存されたデータを古いアプリで開いた場合は、書き換えずに再読み込みを促す
- バックアップの復元は、今のデータを丸ごと置き換える。古い版のバックアップは変換し、新しい版のものは受け付けない

## 計算ルール

- 収入 ＝ 手取り月収 ＋ 副業収入 ＋ その他収入（＋ ボーナス÷12：「毎月に換算」を選んだ場合）
- 自由に使えるお金 ＝ 収入 − 固定費 − 生活費予算 − 貯蓄予定 − 積立投資 − 目的別の積立
- 目的別の貯金（車・引っ越し・家具など）：運用益なしで、購入予定月の前月までの残り回数で残額を割り、100円単位で切り上げた額を毎月積み立てる。今月分を積み立て済みなら来月から数え直し、今月は実際の積立額を差し引く。各目的の「今の残高」は現在の貯金額の内訳として扱い、将来の資産シミュレーションからは除く。「購入済みにする」で現在の貯金額から残高を差し引いて終了
- 支出カテゴリは「生活費」（食費・日用品・交通費・医療）と「自由費」（外食・趣味など）に分かれる。生活費予算を超えた分は自由に使えるお金から差し引く
- 「今月」は給料日で区切る（給料日25日なら 25日〜翌月24日。1日なら暦どおり）。給料日は1〜28日で設定
- 今日の目安 ＝ 今日の開始時点の残額 ÷ 次の給料日前日までの残り日数 − 今日の支出
- 今週あと ＝ 週初め（月曜。期間の初日をまたぐ場合は初日）の残額 × 今週の日数 ÷ 週初めからの残り日数 − 今週の支出
- 将来貯蓄 ＝ 現在の貯金（目的別の残高を除く）＋ 毎月の貯蓄 × 12 × 年数 ＋ ボーナスから貯金に回す年額 × 年数（利息なし）
- ボーナス（別管理）：支給月と、1回あたり「貯金に回す額」「各目的別へ入れる額」を決める。購入予定月の前月までに受け取る予定のボーナス分だけ、目的別の毎月の積立額が減る。受け取ったら記録すると、貯金額と各目的の残高に加える
- 設定の履歴：収入・固定費・生活費・貯蓄・積立投資を、設定を変えた期間の初日から有効な記録として残す。グラフや期間の締めは、その期間の設定で計算する
- 期間の締め：前の期間の「その期間の設定による自由に使えるお金 − 実際に目的別へ積み立てた額 ＋ 繰り越し − 使った額」を、貯金へ回す／目的別へ入れる／今の期間へ繰り越す（マイナスなら貯金から補てん／今の期間から差し引く）から選ぶ
- クレジットカード：毎月の請求額を1回入れると、その期間の引き落とし日（「毎月○日」、ない月は月末）の支出（カテゴリ「クレジットカード」・自由費）として記録する。同じ期間に入れ直すと上書き。生活費予算があると二重計上の注意と「0円にする」ボタンを出す
- カードの利用額：締め日（31＝月末）で区切ったサイクルごとに、カード会社のアプリで見た利用額をときどき記録。あと使える額 ＝ 上限 − 最後の利用額（上限は自分で決めた額、0なら毎月の自由に使えるお金）、1日あたり ＝ あと使える額 ÷ 締め日までの日数、請求見込み ＝ 利用額 ÷ 経過日数 × サイクルの日数。請求は締め日の翌月の引き落とし日
- 積立投資をカードで払う（積立投資の「クレジットカードで積み立てている」）：請求額を記録するときに毎月の積立額を investPart として残し、支出として数える額は 請求額 − 積立分（spendAmount）。カードの利用額も 利用額 − 積立額 を上限と比べ、請求見込みには積立分を足して表示する
- 請求額のふり返り：今回の請求額を直前3回の平均と比べ、10%以上多い・少ないときに知らせる。家計簿のグラフに請求額の推移（直近6回と平均）
- 表示モード：「カード中心」では生活費予算・使い道・予算の目安・出費判定・予算消化・最近の支出・カテゴリ追加などを隠し、ホームを「カードであと○円」にする。切り替え時に生活費予算を0円にする（元に戻せる）
- 給料日のお知らせ：給料日（毎月）とボーナス月（毎年）の朝9時の予定をカレンダー形式（.ics）で書き出し、端末のカレンダーで通知する（サーバーを使わないため）
- 積立投資 ＝ 月複利（月利＝想定年利÷12、毎月末に積立）。税金・手数料・価格変動は含めない想定シミュレーション
- NISA枠チェック：つみたて投資枠 年120万円／年間合計 360万円／生涯 1,800万円（元本ベース）
- 使い道ごとの予算 ＝ 自由に使えるお金 × 割合（0〜50%）。週予算 ＝ 月予算 × 12 ÷ 52、外食の1回あたり ＝ 週予算 ÷ 週の回数
- 予算の目安（手取り比）：固定費40%・食費13.3%・日用品3.3%・交通費3.3%・貯蓄23.3%（積立投資分を差し引く）、自由費の配分は外食30%・趣味20%・娯楽20%。今の期間を除く直近3期間に記録があれば、その実績平均を優先
- よく使う支出：直近90日でカテゴリ・店名・金額が同じ記録が2回以上あるものを、回数の多い順に最大6件。タップで今日の日付で記録（取り消し可）
- グラフ（家計簿 →「グラフ」）：期間ごとのカテゴリ別支出（横棒）、直近6期間の収支（固定費・生活費・自由費の積み上げ＋収入）、残ったお金の推移（収入 − 固定費 − 記録した支出、今の期間は見込み）。収入・固定費は今の設定額で過去も計算。色は dataviz の検証済みパレット（青・オレンジ・アクア、赤字は赤）
- 金額欄：入力中も 300,000 のようにカンマ区切りで表示。全角数字も受け付ける
- バックアップのお知らせ：一度も保存していなければ使い始めて7日後、保存済みなら前回から30日後にホームに表示。「あとで」で7日間非表示
- 使いすぎ警告：カテゴリ予算の80%以上で「あと○円までなら予定内」、超過で調整の案内
- 目標逆算：必要な月額 ＝ (目標 − 現在の貯金・投資) ÷ 月数（運用ありは年金現価の逆算）。今の貯蓄＋積立で届くか判定し、届かなければ不足額と到達までの期間を表示
- 昇給・転職：n年後の手取り ＝ (現在 ＋ 転職増額) × (1 ＋ 昇給率)^n。増えた分 × 貯蓄に回す割合 を累計
- 家計診断：貯蓄率（貯蓄＋積立）・固定費率・自由支出率で 🟢かなり余裕あり／🟢安定／🟡普通／🟠注意／🔴要見直し
- 節約効果：見直し前後の差額 × 12か月・10年、運用した場合は想定利回りで積立計算

## スマートフォンで使う（公開）

PWA（ホーム画面に追加・オフライン）は HTTPS で配信したときに有効になる（localhost は例外）。
`public/` フォルダをそのまま静的ホスティングに置けばよい（GitHub Pages / Netlify / Cloudflare Pages など。ビルド不要）。
サブディレクトリ配信でも動くよう、パスはすべて相対パスにしている。

アプリのファイルを追加・削除したときは `public/service-worker.js` の `SHELL` を更新し、`CACHE` の番号を上げる。

## Google Play で公開する

[docs/google-play.md](docs/google-play.md) の手順で、PWA を TWA として包んで出す。プライバシーポリシー・利用規約は `public/privacy.html`・`public/terms.html`（設定画面の下からリンク）。データの扱いや有料機能を変えるときは、この2つと制定日も更新する。

## 使い方ガイドの追加・修正

機能を追加・変更したら、`public/js/guideContent.js` の `GUIDES` に説明を書き、画面の見出しに `helpBtn('id')` を置き、`SCREEN_GUIDES` のその画面の一覧に id を加える。
`npm test` で「?」に対応するガイドがあるか・リンク切れがないか・どの画面からも開けるかを確認できる。
